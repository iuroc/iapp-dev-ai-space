# 环境适应：先问能力，再选通道

> **读法**：参考，不是强制流程。产品名只作例子；具体读数以当前机器实测为准。
> 换一台机器、换一个模拟器、换成真机时先读这篇，再决定投递与取证怎么做。

## 一句话

「这台机器能做什么」决定「工程怎么送进去、证据怎么拿出来」；
不要照抄上一台机器的路径、端口、工程根。

## 能力维度

| 维度 | 为什么要看 | 怎么看 |
|---|---|---|
| 宿主 OS / 版本 | 决定 shell 语法、路径改写、可用工具 | `platform` / `systeminfo` |
| 宿主虚拟化 | 开了 Hyper-V 时 VirtualBox 系模拟器通常起不来 | `HypervisorPresent`、实际能否启动 |
| 承载产品 | 决定默认共享目录、默认端口、root 机制 | 安装目录、注册表、运行进程 |
| Android / API | 决定分区存储、`Android/data` 可见性、权限模型 | `getprop ro.build.version.sdk` |
| adb 可达 | 能否 `force-stop`、拉 `logcat`、`screencap` | `adb devices -l` 有没有 `device` 行 |
| root / su | 安卓 11+ 改工程根、`Android/data` 里建链接需要 | `su -c id` / `adb root` |
| 共享目录 | 有没有「宿主目录 ≡ 设备目录」这条捷径 | 产品设置 + 设备侧 `ls` |
| 存储权限 | 工程根与共享目录能否被读写 | `appops get <包名> MANAGE_EXTERNAL_STORAGE` |
| iApp 工程根 | 所有投递的落点 | iApp 设置里显示的「存储路径 / 工程路径」 |
| FTP 可达 | 有没有一条纯网络的文件通道 | 见 `ftp-delivery.md` |

## 未知宿主勘测清单（五件事，按顺序）

1. **设备能起、iApp 已装**：起不来的话后面都不用谈。
2. **`adb devices -l` 有没有 `device` 行**——判据是「有设备」，不是「adb 可执行」。
   有些产品自带 `adb.exe`，能跑但看不到容器里的设备 ⚠。
3. **iApp 设置里显示的工程根**：以它为准，不要用「默认路径」猜。
4. **有没有共享目录**：产品设置里找「共享文件夹 / 共享目录」，再看设备侧挂到哪个路径。
5. **FTP 能不能登**：宿主能不能连；宿主不通时设备内连 `127.0.0.1:<端口>` 能不能通。

五件事里缺哪一项，就在结论里标 ❓ 并写清「怎么验」，不要用「应该 / 通常」代替。

## 通道选择

### 先判断「宿主能不能直达」

FTP 类通道先分两种情况，判据是**能不能从宿主建立 TCP 连接**，不是 ping 通不通（ICMP 常被禁）：

| 判法 | 命令 |
|---|---|
| Windows | `Test-NetConnection <设备IP> -Port <端口>` |
| 任意 | `nc -vz <设备IP> <端口>`，或直接让客户端连一次 |
| 不行时 | 改用 `adb forward`（见下） |

- **能直达** → 用设备给的地址直连，最省事。
- **不能直达，但有 adb** → 隧道：`adb forward tcp:<端口> tcp:<端口>`，连 `127.0.0.1:<端口>`。
  协议若会「自报地址 + 另开端口」（FTP-PASV、RTSP…），还要**逐个数据端口转发**或改写响应地址。
- **既不能直达、也没有 adb** → FTP 从宿主侧就到不了，只能换通道或改网络模式（桥接 / 端口映射）。

「网络不互通却能连」并不矛盾：直连走 IP 网络，`adb forward` 走的是 adb 这条管理通道，
在它上面开了根管子。两条路指向同一个服务。

### 推荐优先级（按开发用途，不按能不能连）

| 位次 | 通道 | 什么时候它最优 | 主要代价 |
|---|---|---|---|
| 1 | 共享目录镜像 | 日常改码、一次改多个文件、频繁预览 | 有缓存/截断坑，改完必须核设备侧 md5；取证要另配 adb |
| 2 | `adb push/pull` | 单文件精确改、需要 `logcat`/`screencap`、共享目录核不上 | 需要 adb |
| 3 | FTP 直连 | 没有共享目录、也没有 adb，但宿主能直达 | 没有日志、不能 `force-stop`、整文件传 |
| 4 | FTP over `adb forward` | 有 adb，但宿主到设备网络不通 | 逐数据端口转发，连接更脆 |
| 5 | 手工导入（`.iApp` / 文件管理器） | 以上全不通 | 人工、慢、易错 |

**最佳组合**：有共享目录 + 有 adb 时，**写用共享目录、取证用 adb**——省掉整文件传输，又能拿日志。

> FTP 直连排在 adb 之后，是因为开发更依赖反馈（`logcat`/`screencap`/`force-stop`）而不是连接难度。
> 只做「把文件送进去」时，直连完全可以排第一。

### 决策顺序

```
宿主能直达设备服务端口？
  ├─ 能 → 有共享目录？共享目录镜像（更省事）
  │        否则 → FTP 直连
  └─ 不能 → 有 adb 设备行？
        ├─ 有 → 共享目录可用？写共享目录 + adb 取证
        │        否则 → adb push/pull
        │        （FTP 只在需要第二条文件通道时用，走 adb forward）
        └─ 无 → 只能手工导入 / 改网络模式
```

要点：

- 多通道同时可用时，**同一时刻只走一条写通道**，避免互相覆盖。
- 通道不可用时要能说清是哪一层不通：设备没起、adb 没连、网络不通、路径不对、权限不够。

## 共同铁律

1. **改前关工程**：iApp 以内存为准，运行/保存会用旧内存覆盖磁盘。有 adb 就 `am force-stop`；
   没有 adb 就请用户在界面上关掉工程。
2. **全量推**：只传完整文件、二进制模式，不做增量猜测、不做换行转换。
3. **推完核字节**：能 `md5` 就 `md5`，否则核 `SIZE`；核不上不算完成。
4. **失败重跑到干净**：截断、部分同步、旧缓存都不算成功，重传或换通道。
5. **不用 bind mount**：应用有独立 mount namespace，后加的挂载对 app 不可见 ✅。
6. 改完不要再 `force-stop`，交给用户重新打开工程。

## 版本政策

- 【荐】**优先高版本**：新功能与验证默认在当前最高的 Android 上做（写成这条时是 API 34）。
- 【荐】API 28 及以下**只做有限兼容**，且要开发者明确要求才投入；不追求低版本结论与高版本追平。
- 本库未标版本的结论默认按 API 34 成立；低版本有差异的地方单独标 ⚠。

## 没有 adb 时怎么取证

`logcat`、`screencap`、`am force-stop` 都拿不到，改用：

| 手段 | 怎么做 | 局限 |
|---|---|---|
| 屏幕现象 | 用户看界面、截图发回 | 只能看到最终呈现 |
| 界面内打印 | mjava 把结果写进 `TextView`（不要只 `i.syso`） | 需要改页面 |
| 应用内自检 | `loading` 事件里跑用例，结果上屏 PASS/FAIL | 同上 |
| 服务端回显 | FTP 的 `SIZE`/`MD5`、脚本汇总 | 只能证明文件层 |

需要 `logcat` 才能定位的问题，要明确告诉用户「当前环境没有日志通道」，而不是猜。

## 环境提示（可追加的参考记载）

写法：**当用户处于 X 环境、在做 Y 时，或许可以这样 Z；实际可用性需实测**，
每条带 `✅/⚠/❓` + 版本前提 + 来源类型（实测 / 推导）。产品名只作例子。

| 环境 | 在做 | 或许可以 | 级别 |
|---|---|---|---|
| 只装了 iApp、没有 adb 的容器（如应用宝电脑版这类） | 投递工程 | 评估 iApp 内置 FTP；宿主网络不通时先试 `adb forward`（若尚有 adb），否则在设备内终端验证协议 | ⚠/❓ |
| iApp 跑在 PC 容器里、验收目标却是外接真机 | 开发 → 打包 → 装机 | 容器内打包，`bin/<包名>.apk` 用 FTP `RETR` 取回宿主，再 `adb install -r`；打包前务必在【打包设定so库】勾齐目标 ABI | ✅（2026-10-28，应用宝容器 + OPPO Watch X2） |
| 圆屏手表（如 466×466 / density 320） | 做界面 | 按 dp 画布（约 233dp）设计，内容收进内接正方形（直径 / √2）并居中；`layout_gravity` 别指望，用 mjava `LayoutParams` | ✅（API 30） |
| 手表插 USB 调试 | 截图 / 测按键 | 先 `svc power stayon usb` 防息屏，再用侧键事件（如 `input keyevent 131`）让开充电全屏界面，`mCurrentFocus` 是目标窗口后再 `screencap` | ✅（OPPO Watch X2 / API 30，2026-10-29） |
| Android 11+ 模拟器 + 共享目录 | 改已存在的文件 | 改完核**设备侧 FUSE 视图**（`/sdcard/...`）的 md5；直挂视图可能已新、FUSE 视图仍旧 | ✅（API 34） |
| Windows + Git Bash | `adb push` / 传远程路径 | 先 `export MSYS_NO_PATHCONV=1`，否则 `/storage/...` 会被改写成盘符路径 | ✅ |
| 宿主必须开 Hyper-V（如跑 Docker Desktop） | 跑安卓模拟器 | VirtualBox 系的模拟器多不可用；评估产品自带容器 + FTP 通道 | ⚠ |
| API 28 设备 | 开发新功能 | 只做有限兼容；不要把 API 34 的行为当成两端一致 | ✅ |
| 同一台宿主开了两套雷电 | 投递 | 先 `getprop ro.build.version.sdk` 核对型号；实例序号与宿主端口相关，名字不可信 | ✅ |

新增一条时：先写进证据账本（日期 + 原始读数），再把这条「当…可试…」补进上表。

## 失败签名 → 换通道

| 现象 | 更像哪一层的问题 | 下一步 |
|---|---|---|
| 设备在列表里是 `offline` / `unauthorized` | adb 连接 | 重启 adb server / 在设备上确认授权 |
| `adb devices` 为空但产品在跑 | 产品与 adb 不连通 | 换 FTP 或手工导入 |
| 宿主改了文件，设备看不到 | 共享目录 / 缓存 | 关工程重开；核设备侧 md5；换 `adb push` |
| 设备侧文件字节数少于宿主 | 共享目录截断 | 重传；换 `adb push` |
| `Permission denied` 写工程根 | 权限 / 存储授权 | 补 appop 或换有权限的路径 |
| 连不上设备侧服务端口 | 网络可达性 | `adb forward`、改桥接、或设备内自连验证 |
