# iApp 内置 FTP 投递通道

> **读法**：FTP 是**通用投递通道**，与共享目录、`adb push` 并列，不绑定任何模拟器或应用商店。
> 任何「设备装了 iApp + 在 App 内开了服务器控制台 + 宿主网络能到」的 Android 设备都可能用得上：
> 模拟器、真机、同 WiFi 的平板都算。
> 级别：✅ 实测 / ⚠ 有条件或未复验 / ❓ 未测。标注「单机」的表示只在一台设备上测过。

## 1. 一句话

iApp 的「服务器控制台」会给出一个 `ftp://<设备IP>:<端口>`；连上去看到的是 **iApp 应用级文件区**，
工程在 `/ProjectApp/<项目ID>`。没有 adb 时，这是唯一能成规模传文件的通道。

## 2. 适用条件

| 条件 | 说明 |
|---|---|
| 设备装了 iApp | 服务端在 iApp 进程内，不是系统服务 |
| 服务器控制台已开 | 端口由 App 给出，**每次可能不同**，要现抄 |
| 宿主网络可达 | 模拟器 NAT 端口映射 / 真机同网段；不满足见 §7 |
| 不需要 root | 服务端读写的是 iApp 自己的文件区 |

**与「Android 11+ `Android/data` 不可见」的关系**：那条限制约束的是**第三方** FTP 服务端
（别的 app 看不到 iApp 的 `Android/data`）。iApp 内置的服务端跑在 iApp 自己进程里，
天然能看到自己的工程区 ✅（单机，2026-10-27）。不要把两者混为一谈。

## 3. 路径模型

```
宿主工程镜像  ──FTP──>  FTP 根（iApp 应用级文件区）
                          ├── ProjectApp/<项目ID>/     ← 工程在这里
                          ├── DownloadFileDir/
                          ├── Userimg/
                          ├── screenshot/
                          └── *.txt（手册副本）
```

- 远端路径要写**以 `/` 开头的绝对路径**，如 `/ProjectApp/<项目ID>/src`
- 工程根不一定等于 FTP 根：常见是 FTP 根的子目录，先 `CWD` / `LIST` 确认再传

## 4. 实测特性

| 项 | 结果 | 级别 |
|---|---|---|
| 登录 | 匿名 `anonymous` + 任意邮箱可用 | ✅（两台机器） |
| `FEAT` | 至少包含 `SIZE` `MDTM` `REST STREAM` `MLST` `AUTH TLS` `MODE Z` `UTF8` `TVFS` `MD5` `MMD5` `MFMT`；**不同环境列出的项不完全一样**（有的列 `MLSD`，有的不列但可用） | ✅（两台，清单有差异） |
| 写权限 | `STOR` / `DELE` / `MKD` / `RMD` / `RNFR`+`RNTO` / `APPE` 全部可用 | ✅（两台，2026-10-28） |
| 目录列表 | `MLSD` / `NLST` 可用 | ✅（两台） |
| 点开头文件 | 列表**不显示** `.project`；`SIZE` / `MD5` 正常（实测 145B 与本地一致） | ✅（两台） |
| 父目录 | `STOR` **不会**自动建父目录，报 `551 Error on output file`；`MKD` **也不是递归的**（父不存在报 `550`），必须逐级建 | ✅（单台，2026-10-28） |
| 传完校验 | 服务端 `MD5` 与本地一致（没有共享目录那种旧缓存问题） | ✅（读侧两台） |
| 宿主直连 | 取决于网络：NAT/隔离时不可达，但服务端正常 | ✅（两台，结论因环境而异） |
| 控制端口经 `adb forward` | 可登录；**但 PASV 数据端口仍需逐个转发** | ✅（单台，2026-10-28） |
| 主动模式（PORT） | 不可用，报 `425 Can't open data connection` | ✅（单台） |
| 断点 / 追加 | `REST 100` + `RETR` 只收到剩余字节；`APPE` 正确追加 | ✅（单台，2026-10-28） |
| 中文文件名 / 编码 | UTF-8 正常，含中文与空格的路径可 `STOR`/`SIZE`/`DELE` 往返 | ✅（单台，2026-10-28） |
| FTPS | `FEAT` 有 `AUTH SSL` / `AUTH TLS`，未实连 | ❓ |

## 5. 坑

1. **点文件只能直探**：`MLSD`/`NLST` 看不到 `.project`，用清单判断存在性会反复重传。
   用 `SIZE` 探（返回 213 + 数字即存在，`0` 也是合法值；550 视为不存在）。
2. **`STOR` 不建父目录**：先按深度逐级 `MKD`（已存在会报 550，`CWD` 验证后继续）。
3. **端口每次可能变**：从 iApp 界面现抄，不要写死。
4. **Git Bash / MSYS 改写路径**：`/ProjectApp/...` 会被改写成 `C:/Program Files/Git/ProjectApp/...`。
   用 Python 脚本传路径、或 `export MSYS_NO_PATHCONV=1`。脚本应拒绝桶形路径并提示。
5. **不要用 `curl -Q`**：引号语义容易被 shell 吃掉，行为不稳定；用 `ftplib` 或脚本。
6. **工程必须关着**：iApp 以内存为准，开着工程时保存/运行会用旧内存覆盖刚传上去的文件。
7. **别把「0 个文件」当成成功**：远端根不存在时，列表命令可能只是失败后被吞掉。
   拉取前先 `CWD <远端根>` 校验，失败就报错退出。
8. **删目录要连点文件一起删**：按 `MLSD` 列表删完文件后 `RMD` 仍会报
   `450 Can't remove directory`，因为 `.project` 这类点文件根本不在列表里——要按 `DOTFILES` 点名删。

## 6. 脚本

`scripts/ftp_sync.py`（纯标准库）：

```bash
# 预演（只读，列出远端树与差异）
python scripts/ftp_sync.py --host <设备IP> --port <端口> \
  --remote /ProjectApp/<项目ID> --local-root <宿主工程目录> --dry-run

# 推（全量 + SIZE/MD5 校验，退出码 0 才算完成）
python scripts/ftp_sync.py --host <设备IP> --port <端口> \
  --remote /ProjectApp/<项目ID> --local-root <宿主工程目录>

# 拉（首次建立镜像 / 回滚）
python scripts/ftp_sync.py --host <设备IP> --port <端口> \
  --remote /ProjectApp/<项目ID> --local-root <宿主工程目录> --pull

# 宿主到设备网络不通、但有 adb：让脚本自己转发控制端口与每个数据端口
python scripts/ftp_sync.py --adb-forward <serial> --port <端口> \
  --remote /ProjectApp/<项目ID> --local-root <宿主工程目录> --dry-run
```

- 默认只清理 `--managed-dirs`（`src,sdk`）内的多余文件；默认**不删**远端其它文件
- 服务器不支持 `MD5` 时降级为只核 `SIZE`，并在汇总里标 ⚠
- 非零退出码都表示没传干净，重跑到 0

## 7. 直达还是隧道

先判断宿主能不能直达设备给出的地址（判据是 TCP 能连，不是 ping 通）：

```powershell
Test-NetConnection 192.0.2.10 -Port <端口>     # Windows（示例网段；端口以 iApp 界面为准）
```

- **能直达** → 直接用 `ftp://<设备IP>:<端口>`，最简单。
- **不能直达，但有 adb** → 走 `adb forward` 隧道（下表第一行）。
- **既不能直达、也没有 adb** → 宿主侧无解，换通道或改网络模式。

宿主与设备不在同一可路由网络（NAT、网关隔离、公司网段）时，宿主侧 FTP 不通——**这不代表服务端坏了**。
通道优先级（含共享目录、adb）见 `references/environment-adaptation.md`。

| 办法 | 做法 | 代价 |
|---|---|---|
| `adb forward` + 逐数据端口转发 | 先转发控制端口；**再对每个 PASV 数据端口各转发一次**，连接改走 `127.0.0.1` | 需要 adb；每次数据连接都是新端口，必须动态转发 ✅（单台，2026-10-28） |
| 设备内自连 | 设备内终端（如 MT 管理器的终端、Termux）连 `127.0.0.1:<端口>` | 只能验协议，**不能当投递通道** |
| 改桥接 / 端口映射 | 模拟器网络模式从 NAT 改桥接，或加端口映射 | 产品相关 ⚠ 未验 |
| 换通道 | 有 adb 就 `adb push`；有共享目录就走镜像 | — |

`ftp_sync.py --adb-forward <serial>` 已实现第一种：控制端口自动转发，PASV 数据端口在
`makepasv()` 里逐个转发，退出时清掉。**主动模式不要用**（实测 `425`）。

**人工验证交接**：宿主不通时，可以让用户在设备终端里跑一组带编号的命令，把整段输出贴回。
命令优先 `curl` / `busybox ftpget`，都不存在时用 mjava `java.net.Socket` 写个最小 FTP 客户端探针
（结果直接上屏 + `ygs`），不要假设设备装了 ftp 客户端。

## 8. 与另外两条通道对照

| 维度 | 共享目录 | `adb push` | FTP |
|---|---|---|---|
| 前提 | 产品支持共享目录 | adb 能看到设备 | 宿主网络可达 + 控制台已开 |
| 方向 | 双向实时 | 双向按需 | 双向按需 |
| 认证 | 无 | adb 授权 | 匿名（默认） |
| 能否 `force-stop` | 否（需另配 adb） | 能 | 否 |
| 能否 `logcat` / `screencap` | 否（需另配 adb） | 能 | 否 |
| 校验 | 核设备侧 md5（有缓存坑） | `md5sum` | `SIZE` + `MD5`（服务端支持时） |
| 典型失败 | 截断、FUSE 旧内容 | 权限、路径 | 端口变、父目录不存在、点文件看不见 |

结论：按环境选，不存在「永远更好」的一条。

## 9. 失败签名

| 签名 | 含义 | 处理 |
|---|---|---|
| `530 Login incorrect` | 认证失败 | 匿名 + 任意邮箱；不改密码不重试 |
| `550 Failed to change directory` | 远端根不存在 / 无权限 | 先 `LIST` 根，确认工程路径 |
| `553 Could not create file` | 父目录不存在 / 只读 | 逐级 `MKD` 后重试 |
| `551 ... Error on output file` | 父目录不存在（iApp 实测返回码） | 先逐级 `MKD`；`MKD` 本身也不递归 |
| `550 Can't create directory` | `MKD` 的父目录不存在 | 从远端根开始一级一级建 |
| `425 Can't open data connection` | 被动模式端口被挡 | 换网络 / 开被动端口范围 |
| `421 Timeout` | 空闲超时 | 重连；缩小批次 |
| `SIZE` 550 但文件确实在 | 模式或路径不对 | 先 `TYPE I`；确认绝对路径 |
| 传完 `SIZE` 为 0 或小于本地 | 截断 | 重传；必要时换 `STOR` 临时名再改名 |
| 列表里没有 `.project` | 服务端不列点文件 | 用 `SIZE` 探 |

## 10. 安全边界

- FTP 默认是**匿名 + 明文**：只在可信局域网/同一台宿主机使用；用完关掉服务器控制台。
- 不要把端口暴露到公网；不要用 FTP 传凭据或私密数据。
- 不要把整个 `/sdcard` 或 `/` 暴露成 FTP 根；根应只覆盖工作需要的目录。
- 别人的机器上抓到的 IP、端口、账号，不要当作通用默认值写进文档。
