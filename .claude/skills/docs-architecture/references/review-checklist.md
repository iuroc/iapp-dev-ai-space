# 语义审手册

> 脚本负责机械项（见 `scripts/review_docs.py`）；本文件负责**脚本判不了**的部分。
> 每条给「怎么判 / 合格标准 / 真实反例」，反例都来自本仓库 2026-10-28 的体检。

## 五问（每次审阅都过一遍）

1. **每条 ✅ 能指到 evidence 的日期/批次吗？** 指不到就是越级。
2. **这条结论的主文件是不是它所在的文件？** 对照 `architecture.md` 的查表。
3. **两处数值不同：同一对象吗？同一时间吗？同一层吗？** 三问有一否即非冲突。
4. **`--help` 说的行为，代码真这么做吗？** 文档与实现分离时优先信代码，改文档或改代码。
5. **迁移/精简后，原文删干净了吗？** 没删就是重复 +1。

## A 层级归属

| 判据 | 合格标准 | 真实反例 |
|---|---|---|
| A1 SKILL 无本机事实 | 无 IP、端口、serial、盘符、真实包名、单机日期 | `.claude/skills/iapp-development/references/ftp-delivery.md` 写了具体 IP 与端口；`.claude/skills/iapp-development/scripts/ftp_sync.py` docstring 写 IP 和盘符 |
| A2 CLAUDE.md 不教语法 | 只讲「这台机器怎么做事」 | 文档里出现某控件怎么写、某 API 怎么调 |
| A3 docs 不写通用方法 | 通用结论在 SKILL，docs 只写读数 | 环境档案里写「安卓 14 建软链要用 su」的完整步骤（应指向 SKILL） |
| A4 决策规则在 CLAUDE.md | 优先级、设备选择、变量顺序 | 同一优先级表同时出现在 CLAUDE.md 与 `environments/README.md` |

## B 去重

| 判据 | 合格标准 | 真实反例 |
|---|---|---|
| B1 结论单一主文件 | 改一处不会漏改另一处 | FUSE 旧缓存结论散落 7 个文件；MSYS 6 处；bind mount 6 处 |
| B2 元规则不双写 | 级别/引用/索引规则只在 skill | `级别只升不降` 在 CLAUDE.md 与 `environments/README.md` 各一份 |
| B3 同指标单值或分口径 | 真冲突只留一个；假冲突拆两条 | `targetSdk` 37/36 被当成矛盾 |

## C 标注

| 判据 | 合格标准 | 真实反例 |
|---|---|---|
| C1 三件套齐全 | 级别 + 来源 + 日期 | 能力矩阵多数格子只有 ✅ |
| C2 他机不超过 ⚠ | 他机/交接/口述一律 ⚠ | 他机 FTP 读数写成 ✅（5 处） |

| C5 级别与证据相称 | 实测不可达就写 ❌ 或 ✅ 不可达 | 实测不可达却标 ⚠「口述」 |

## D 索引与引用

| 判据 | 合格标准 | 真实反例 |
|---|---|---|
| D1 索引完整 | 实际文件 ⊆ 最近一层索引 | `scripts/README.md` 漏 `dex_common.py` |

## E 脚本与文档

| 判据 | 合格标准 | 真实反例 |
|---|---|---|
| E1 参数都文档化 | 每个 `--x` 至少出现一次 | `--delete-extras` 从未写进文档 |
| E2 示例命令可执行 | 必填参数齐全、参数名存在 | CLAUDE.md 的 FTP 示例缺 `--remote`；`detect_env.py --ftp` 未见于文档 |
| E3 help 与实现一致 | 行为描述不夸大 | `--tls` help 说「失败退回明文」，实现直接报错 |

## F 结构与格式

| 判据 | 合格标准 | 真实反例 |
|---|---|---|
| F1 环境档案骨架完整 | 元信息 / 识别 / Android / 投递 / 工程根 / 权限 / 坑 / 未测 / 取证 | — |
| F2 evidence 条目格式 | `## YYYY-MM-DD 批次 标题` + 原始读数 + 结论 | 部分条目把批次写进括号 |
| F3 新 skill 自洽 | 自己的 references 进导航、无行号引用、无真实 IP | 新建时先自审，零发现再纳入全仓 |

## 脚本判不了的三件事（必须人工）

1. **结论是否仍然成立**——数值对得上，但事实可能已变。
2. **主文件选择是否正确**——文件里确实只有一条，但放错了层。
3. **重复的语义等价**——换了措辞的同一结论，shingle 相似度可能不够高。

## 误报处理

| 情况 | 处理 |
|---|---|
| `docs/evidence.md`、`docs/superpowers/plans/`、`docs/superpowers/specs/` 的旧引用 | 标「历史，仅提示」，不计阻断 |
| 占位符路径（含 `< > * ?`） | 跳过，不判死链 |
| 索引行与正文重复短语 | 不判重复 |
| `targetSdk` / UID 等已知分口径指标 | 只报组，人工确认 |
| 文档网段 IP（`192.0.2.x`） | 允许出现在示例命令里 |
