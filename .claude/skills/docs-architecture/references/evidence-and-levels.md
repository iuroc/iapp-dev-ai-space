# 证据与级别：一条知识该怎么写

> 本文件是「标注」的规范正文，其他文件只写指针，不复制。

## 1. 记号语义

| 记号 | 含义 | 必要条件 |
|---|---|---|
| ✅ | 实测通过 | 必须能指到某条原始读数（日期或批次） |
| ⚠ | 有条件成立 / 他机读数 / 口述 / 未复验 | 必须写清条件或来源 |
| ❓ | 未测 | **必须同条写「怎么验」**，只标 ❓ 视为未完成 |
| ❌ | 实测不可用 | 附失败签名或错误码 |
| — | 不适用 | 无需说明 |

## 2. 升降规则

```
❓ 未测  →  ⚠ 有条件/他机  →  ✅ 本机实测
```

- **只升不降**；升级必须给出新的原始读数，不能靠推理。
- **他机读数上限是 ⚠**：别的机器上测到的，无论多确定，都不能标本机 ✅。
  同一结论若两台机器都测过，写「✅（两台）」，其中一台是他机时仍按 ⚠ 记，并注明另一台来源。
- 降级只允许一种情况：发现了反例，且反例本身进了 `docs/evidence.md`。
- 同一格子/同一行不得同时出现 ✅ 与 ⚠。

## 3. 每条事实三件套

**级别 + 来源 + 日期**。三者可以在表格同一格内合并，但必须都在。

| 好 | 差 |
|---|---|
| `✅（2026-10-28，adb 实测）` | `✅` |
| `⚠（他机 2026-10-27，未复验）` | `支持` |
| `❓ 怎么验：设备内终端连 127.0.0.1:<端口> 跑 FEAT` | `❓ 待测` |

来源类型要写清：实测 / 推导 / DEX 静态分析 / 官方文档 / 用户口述。

**口径必须写清**。同一个名字可能指两个对象，典型：

- `targetSdk`：**iApp 安装包** 与 **打包产物** 是两个值（37 / 36），不是冲突。
- `UID`：iApp 进程 UID 与文件属主 UID 可能不同，重装会变。

## 4. 证据链

```
docs/evidence.md（原始读数，只追加）
    ↓ 提炼
docs/environments/<环境>.md（长期事实，带级别/来源/日期）
    ↓ 提炼
SKILL（通用结论，带版本前提 + 级别）
```

每一步都必须能回溯：SKILL 的结论要能在档案里找到依据，档案要能指到 evidence 的日期/批次。
只写结论不写出处，下一轮就无法判断它还成不成立。

## 5. `❓` 的可验写法

三种都算合格：

1. **一条命令**：`adb shell getprop ro.build.version.sdk`，期望 34。
2. **一个探针**：在 `android-sync/iapp-demo/<批次>/` 建页，`loading` 里跑用例并上屏。
3. **一次人工观察的判据**：打开某页面，看某控件是否出现/是否可点击。

不合格：`待测`、`后续验证`、`需要时再测`、`未验证`（这些只说明「没做」，没说明「怎么做」）。

## 6. 快照 vs 长期事实

会随重装、重开、多开、换网络变化的值，**不进环境档案正文**：

| 值 | 归属 |
|---|---|
| 当前在连设备、serial、端口 | `docs/runtime-env.md` |
| iApp UID、安装时间、版本号 | `docs/runtime-env.md` |
| 安装目录、root 机制、工程根位置、能力矩阵 | `docs/environments/<环境>.md` |
| 一次连接的 FTP 地址 | `docs/evidence.md`（或本机薄包装配置） |

档案里要引用这些值时写「当前值见 `runtime-env.md`」，不要复制。

## 7. 假冲突识别

看到「同一指标两个值」时，按顺序问：

1. **同一对象吗？**（安装包 vs 打包产物、进程 UID vs 文件属主、设备 A vs 设备 B）
2. **同一时间吗？**（重装前后、改设置前后）
3. **同一层吗？**（快照 vs 长期事实；通用结论 vs 某台机器读数）

三问里有一个「否」，就不是冲突，而是**两条各自带限定的记录**。处理方式是拆成两条、各写口径，
不是选一个丢掉另一个。

真冲突（三问全「是」）才按 `architecture.md` 的裁决顺序处理。

## 8. 反例

| 反例 | 问题 |
|---|---|
| 他机 FTP 读数写成 `✅` | 违反「他机上限 ⚠」 |
| 表格里 `✅ 匿名可登录 ⚠ 他机` | 同格双级别，读者无法判断 |
| 实测不可达却标 `⚠（口述不可达）` | 级别低于实际证据，来源写错 |
| 环境档案写当前 UID | 快照混进长期事实，重装后必错 |
| `targetSdk 36 与 37 不符，以 37 为准` | 把两个对象当冲突，会把正确的打包读数改坏 |
