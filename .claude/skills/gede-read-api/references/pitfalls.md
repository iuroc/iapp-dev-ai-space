# 已知坑与失败签名

> 主文件：本文件按「现象 → 原因 → 改法」编排。契约细节见 `references/api-reference.md`。
> 每条都来自青简工程实测；标 ⚠ 的是单平台读数。

## 1. 搜索：输入什么都没变化

**现象**：搜索页无论输什么，结果列表完全一样。
**原因**：`books.jspx` 的 `keyword` 被服务端忽略。参数扫（`keyword/name/title/q/key/word/…`）
全部返回同一 `allCount`；路径扫（`search.jspx` 等）全部报「接口路径错误」。
**改法**：客户端本地建索引，或自建后端代理。详见 `references/integration-guide.md §4`。

✅ 2026-10-28（QJ-P2）。

## 2. 目录跳页总是跳错

**现象**：目录显示「第 100 页」，点进去底部页码是「第 20 页」。
**原因**：用了 `catalogs[].contentIndex` 当页号。它是章节内部序号，不是页号。
**改法**：`idx = catalogs[i].page - 1`，再夹在 `[0, contents.length-1]`。

真实读数：`page=330` 的目录项 `contentIndex=6`，两者早已分叉。

✅ 2026-10-28（QJ-P3）。

## 3. `page` 当成「第几段」

**现象**：翻下一段时内容重复或跳页。
**原因**：`page` 是 **1 基内容起点**，不是段号。`page=2&psize=10` 返回的是第 2–11 页，
与上一段重叠 9 页。
**改法**：`start = floor((N-1)/S)*S + 1`。详见 `references/reading-flow.md §2.1`。

✅ 2026-10-28（QJ-P6）。

## 4. 换设备后页码全错

**现象**：手机上的「第 50 页」在平板上指向别的内容。
**原因**：`w/h/fsize` 变了，服务端重新分页，`pageAll` 与目录页号一起缩放。
**改法**：`w/h/fsize` 全 App 只留一处常量；进度里连同这三个参数一起存，
恢复时参数不一致就按 `page/pageAll` 比例换算。

读数：同一本书 `1000×2000/18 → 84 页`，`400×400/18 → 487 页`。

✅ 2026-10-29（WATCH-3）。

## 5. token 页返回错误页 / 取不到字段

**现象**：`/o/a.h` 返回一段通用页面，正则三个字段全是 null。
**原因**：`surl` 没补协议。图书的 `surl` 是 `gede.5read.com/g/…`，不带 `https://`；
期刊期次的 `surl` 反而带。直接拼 `GEDE:gede.5read.com/…` 会失败。
**改法**：统一 `surl.startswith("http") ? surl : "https://" + surl`，再做 URL-encode。

✅ 2026-10-30 复测（图书 / 期次各一次）。

## 6. 期刊期次查不出来

**现象**：`magazineItems.jspx` 返回 `result:0`，`errorMsg` 为「magazineid参数不符合要求，请确认」。
**原因**：传了刊号 `MZ11000014`。该接口只认**纯数字** `id`。
**改法**：从 `magazines.jspx` 的 `list[].id` 取数字 ID。

✅ 2026-10-27（API-A1）+ 2026-10-30 复测。

## 7. 精品推荐分类是空的

**现象**：`cataid=123` 返回 `result:0`「没有获取到数据」。
**原因**：该分类当前无内容，属正常业务空态。
**改法**：前端按空态处理；不要把 `result:0` 当网络错误重试。

✅ 2026-10-27 普查，2026-10-30 复测。

## 8. 按 `Content-Type` 判断 JSON 解析失败

**现象**：HTTP 库把响应当 HTML 字符串返回，或拒绝解析。
**原因**：所有 JSON 端点的 `Content-Type` 都是 `text/html;charset=UTF-8`。
**改法**：不看 header，直接对 body 做 JSON 解析；失败时再当错误页处理。

✅ 2026-10-30 复测。

## 9. 浏览器里请求全部失败

**现象**：Web 版 `fetch` 报 CORS 错误。
**原因**：服务端不返回 `Access-Control-Allow-Origin`。
**改法**：同源代理，或服务端渲染后回传。详见 `references/integration-guide.md §6`。

⚠ 2026-10-30 单次读数。

## 10. 图片页横向溢出

**现象**：正文出现横向滚动条，图片撑出屏幕。
**原因**：`contents[]` 的 `<img>` 带死值 `width="973" height="1392"`。
**改法**：注入 `img{max-width:100%!important;height:auto!important}`，并关闭横向滚动。

✅ 2026-10-29（WATCH-4，API 30）/ 2026-10-30 复测。

## 11. 详情页想「再拉一次」

**现象**：详情页空白，或设计了一个不存在的详情接口。
**原因**：**没有详情端点**。简介、作者、封面只在列表项里。
**改法**：列表点进详情时把整条记录传过去（内存或本地库），不要重新请求。
列表里没有的字段（如出版社、ISBN）要么列表一起拿，要么放弃。

✅ 2026-10-27 普查，2026-10-30 复测。

## 12. `result:0` 被当成网络故障

**现象**：网络正常但页面反复重试、转圈。
**原因**：`result:0` 是业务态（无数据 / 参数错），HTTP 仍是 200。
**改法**：先判 `result`，再决定「空态」「参数错」「重试」。

✅ 2026-10-30 复测。

## 13. `pageCount` 为 `null` 触发空指针

**现象**：全量拉取后算总页数崩了。
**原因**：`pageSize=-1` 时响应没有 `pageCount` 字段（`allCount` 有）。
**改法**：`pageCount` 只用来做分页 UI；全量模式用 `allCount` 或数组长度。

✅ 2026-10-30 复测。

## 14. 列表字段名两套

**现象**：同一段列表渲染代码处理图书和期刊时字段取空。
**原因**：图书用 `title`/`author`/`cover`/`summary`，期刊用 `name`/`ISSN`/`coverPath`/`summary`，
期次又用 `name`/`issue`/`coverPath`/`magazineItemNum`。
**改法**：进模型前归一化（`Item` 统一成 `title/author/cover/surl`），UI 只认统一字段。

✅ 2026-10-30 复测。

## 15. 目录分页预算没算对

**现象**：阅读器首屏要等好几秒。
**原因**：首屏把 `psize=10000` 整本拉下来。
**改法**：首屏 `psize=0` 只取目录与 `pageAll`（`contents` 为空），正文按 30 页一段拉。

✅ 2026-10-28（QJ-P6）；`psize=0` 的用法 2026-10-30 实测确认。

## 16. 换馆后一切照旧

**现象**：换了一个借阅机 ID，列表为空或全是旧馆内容。
**原因**：`gedeid` 写死在多处，或换了 ID 但没重新普查分类。
**改法**：`gedeid` 只留一处配置；换馆后重跑 `references/api-reference.md §7` 的 18 个分类。

⚠ 未实测换馆；按接口设计推断（报告时间 2026-10-30）。

## 17. token 页取不到三个字段，拿到一段 301 HTML

**现象**：`/o/a.h` 返回 216 B 的 `301 Moved Permanently` 页面，正则 `detailUrl` / `sid` / `from`
全部落空；后面所有正文请求都失败。
**原因**：该端点在服务端已经迁到 `gdread.sslibrary.com`，`gede.5read.com/o/a.h` 只是发 301；
客户端关掉了自动跟随重定向（`setInstanceFollowRedirects(false)`、自建 socket、某些 HTTP 库
默认不跟），于是拿到的就是那 216 字节的跳转页。
**改法**：保持默认跟随重定向；或直接把 token 请求打到 `https://gdread.sslibrary.com/o/a.h`。
其余四个端点仍在 `gede.5read.com` 上直接 200，不要顺手把基址全换掉。

✅ 2026-10-30 实测（`Location: https://gdread.sslibrary.com/o/a.h?...`）。

## 18. 页码越界拿到空内容，还以为书是空的

**现象**：跳转/续读到某一页后正文空白，没有任何报错。
**原因**：`page > pageAll` 时服务端返回 `result:1` + `contents:[]`，不是 `result:0`。
**改法**：请求前把 `page` 夹到 `[1, pageAll]`；收到空数组时按「进度失效」处理，回退到第 1 页
或按比例换算，不要当成网络错误重试。

✅ 2026-10-30 实测（84 页的书，`page=85` / `page=999` 均返回空数组且无 `errorMsg`）。

## 19. 把目录当成平铺列表

**现象**：期刊目录只显示大标题，文章里的小标题全部丢失；或者反过来，把小标题当成独立页跳转，
结果跳到父级那一页，用户以为跳错了。
**原因**：`catalogs[]` 是**树**，`children[]` 可以非空且可继续嵌套；子项的 `page` 有两种形态——
与父页相同（页内小标题，不独立跳转）或不同（独立位置）。
**改法**：按 `pid == 0` 判定顶层，递归渲染缩进子树（深度按 4 层预留）；子项 `page` 与父页相同
时不显示独立页码、跳父页；不同时才当独立目标。

✅ 2026-10-30 实测（期刊 302/302、图书 143/143 子项同页；图书 42/42 子项异页）。
⚠ 深度上限未验证：14 个样本都 ≤ 2 层，但这不足以证明不存在更深的目录。

## 20. 并发把服务端打挂 / 超时

**现象**：全量索引时一半请求超时。
**原因**：18 个请求同时发。
**改法**：串行 + 100–200 ms 间隔；失败重试 1 次即可。

⚠ 经验值，非实测限流数据；限流阈值见 `references/api-reference.md §9` 的 ❓ 项。
