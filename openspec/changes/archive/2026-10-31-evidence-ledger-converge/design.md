# Design

## Context

约束来自 `docs-architecture`（见 proposal 的 Why）：

- `docs/evidence.md` 在规范里被三处定义为「只追加」的历史归档，且被 `review_docs.py` 归入
  `history_files`（问题自动降级）。任何「删了原文」的方案都必须回答「以后靠什么追溯」。
- 20+ 处外部引用按「文件 + 批次 ID」寻址，另有 6 处只写日期。批次 ID 事实上已是外部契约。
- 现有标题层级已损坏：`NAV-8`～`NAV-16`、`XUI-P3/P4` 共 11 个 `###` 子批次挂在无关的
  `##` 之下，按父子结构索引会归错主题。
- `docs/artifacts/` 下多数被引用的文件已不存在（12 处死链），6 处 `android-sync/` 路径已失效。
  这些链接只存在于历史段落里，索引不应复制它们。
- 工作区遵循单分支、按 commit 回退，不推送远程；因此「可回退」的成本很低，
  「可读性」和「不丢结论」才是主要约束。

## Goals / Non-Goals

**Goals:**

- 让 `docs/evidence.md` 从 5537 行降到约 150 行，且**删掉的每一批都能按批次 ID 回查原文**。
- 让 SKILL 内部对同一主题只剩一份正确说法，且这个正确说法在删原文之前就已写好。
- 让体检脚本继续可用：归档不被误当活文档，索引不漏登记。

**Non-Goals:**

- 不重构 SKILL 的文件划分（不合并 `material-*`、不改 `environment-adaptation` 的边界）。
- 不压缩 `SKILL.md` 的「已验证」表，不做 19 簇重复的指针化（用户已定为第二轮）。
- 不修归档文件内部的过时链接与过时结论（冻结快照只加说明头，不逐条更正）。
- 不改工程代码、不动设备侧内容、不跑探针。

## Decisions

### D1 冻结快照 + 重建索引，而不是只靠 git

**选择**：原样复制到 `docs/archive/evidence-2026-10.md`，`docs/evidence.md` 重写为索引。

**备选**：① 直接删，需要时 `git show`；② 只删已吸收批次、保留未决原文；③ 维持只追加。

**理由**：①要改三处「只追加」定义，且读者要会 git 考古才查得到；③不解决文件体积；
②判断成本最高、结果仍是上千行。①+冻结的组合既保住可读性，也不动规范定义。

### D2 索引用日期平铺表，保留批次 ID 作为引用键

**选择**：一行一个批次，列为「日期 / 批次 / 一句结论 / 主文件 / 状态」，按日期排序，
不再沿用现有 `##` 嵌套；`###` 子批次（`NAV-8`、`DOC-4`、`RES-1`、`XUI-P3/P4`）升为独立行。

**备选**：保留 `##` 分节、每节压成 3 行（约 400 行）。

**理由**：127 行可一次读完，且能 `grep -n 'SYNC-2'` 直取；分节版仍在用已经损坏的父子关系。
批次 ID **不得改名、不得合并**——它是外部引用的地址。

### D3 执行顺序固定为「修冲突 → 上浮遗漏 → 删原文」

**选择**：冲突修复与遗漏上浮必须先于索引重建。

**理由**：先删会把「pitfalls #2 的共享目录优先级」「pitfalls #7 的 ppt 默认」这类旧版本
固化成 references 里的唯一说法；一旦原文进了归档，就没人会再去比对。

### D4 未决读数在索引里保留摘要，不只留指针

**选择**：⚠/❓ 批次在索引行内保留读数摘要（数值、现象）与「怎么验」，并在文末设「未决读数」节。

**理由**：工作区的裁决顺序是「原始读数 > 环境档案 > SKILL」。若未决项只剩一个指针，
下次冲突时没有依据可裁。已定级的 ✅ 批次只留一句结论。

### D5 归档文件只加说明头，不做逐条更正

**选择**：文件头写清「冻结快照、只读、批次 ID 是引用键、以现行 SKILL 为准」，并集中列出
已被后续批次推翻的 8 类结论（搜索 `keyword`、XUI 部署现场、设计器四类嫌疑、`NAV-9` 的
「统一 +10000」、设计器「概率性」、共享目录相关、手表 arm64 推断、`targetSdk` 旧口径）。

**备选**：在原段落里逐条插入「已被 X 推翻」。

**理由**：5537 行内联更正成本高、且会让「快照」变成需要持续维护的第三份文档。

### D6 引用迁移按寻址方式分类处理

**选择**：

| 引用形态 | 处理 |
|---|---|
| `docs/evidence.md <批次ID>` | **不改**，索引保留 ID 后继续解析 |
| `docs/evidence.md` + 「完整步骤 / 原始读数 / 见 §某批」 | 改指 `docs/archive/evidence-2026-10.md <批次ID>` |
| 只写日期、无批次号（6 处） | 不改，索引按日期分组可覆盖 |

**理由**：只改真正需要读原文的引用，减少 diff 面积与漏改风险。

### D7 归档文件登记进历史文件与索引

**选择**：`review_config.json` 的 `history_files` 加入 `docs/archive/evidence-2026-10.md`；
`docs/README.md` 新增 `archive/` 一行；`docs-architecture` 的目录布局补 `archive/`。

**理由**：不登记会被体检当活文档，5500 行的死链、过期数值、级别缺失会淹掉真实告警。

### D8 两条无法定案的冲突标 ❓，不阻塞本轮

**选择**：`style-guide.md` 的 Ripple「传 `null` 安全」与 `pitfalls.md` #40 的「无条件 `| 8192`」
一律改成「两种说法并存 + 怎么验」，不猜哪边对。

**理由**：两者都需要一次上机才能定案，为一句话开探针不划算；标 ❓ 符合本工作区的级别制度。

## Risks / Trade-offs

- [删原文后裁决依据变薄] → D4 在索引内保留未决读数摘要，归档可读。
- [索引一行概括丢掉版本/设备前提] → 结论句必须带版本标记（如「API 34」「雷电 9」），
  纯 ✅ 通用结论才允许省略。
- [归档内 12 处 `docs/artifacts/*` 死链] → 冻结文件不修；索引不复制任何死链。
- [一次改 20+ 文件，diff 难审] → 分 4 个 commit（基线 / 修冲突 / 上浮 / 归档+索引），
  每阶段结束跑一次体检。
- [复制 5537 行无法用编辑器整写] → 用文件复制命令完成，`md5sum` 校验一致后再加说明头；
  这是根 `CLAUDE.md` §改动文件的方式 允许的例外（非文本替换），在汇报里说明。
- [批次 ID 被顺手改名导致引用断链] → 索引头部写明「批次 ID 是引用键，不要改名」，
  并在体检时用 `grep` 抽查 8 个被外部引用的 ID 仍存在。

## Migration Plan

1. 阶段 0：提交当前未提交的 5 个文件，建立可回退基线。
2. 阶段 1：修 15 处冲突 → commit。
3. 阶段 2：上浮 18 条结论 → commit。
4. 阶段 3：冻结 + 重建索引 + 迁移引用 + 登记 → commit。
5. 阶段 4：`review_docs.py --fail-on blocker` + `check_portable.py`，修完再提交。

回滚：任一阶段失败即 `git revert` 该阶段提交；归档文件冻结后不再修改，
需要旧原文时 `git show <阶段0的sha>:docs/evidence.md` 仍在。

## Open Questions

无。两条待实机定案的冲突（Ripple 第三参、`8192` 条件）已按 D8 处理为 ❓，
不影响本轮任务拆分；定案后只需改一行级别，不改变方案。
