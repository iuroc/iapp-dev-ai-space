# 2048（经典主题）设计

日期：2026-10-26
环境前提：iApp 5.0.1013、裕 3 模式、LDPlayer9 / Android 9（API 28）、1080×1920 / density 3.0

## 1. 意图

做一款可玩的经典 2048，同时把它当作一次**对现有 SKILL 与工作区文档的压力测试**：
故意用到文档里没写清楚或没验证的能力，用探针把真实行为测出来，再回填。

成功不是"代码写完"，而是三件事同时成立：

1. 游戏在设备上可完整游玩：滑动/方向键、合并计分、动画、胜负、重开、进程杀掉后恢复。
2. 每个新踩到的行为都留下**双证据**：logcat 原文 + 屏幕现象。
3. 探针结束后，SKILL 与 docs 的对应条目已更新；新发现的缺口有明确归属。

## 2. 目标 / 非目标 / 反目标

### 目标

- 标准 4×4 2048，原版配色，完整规则。
- 两种输入：棋盘上滑动、物理/模拟器方向键；两者共用同一个 `move(dir)`。
- 三件套动画：滑动到位、合并放大回弹、新方块弹出；动画期间输入不破坏状态。
- 分数、最高分、当前棋局、胜负状态持久化，杀掉进程后恢复。
- 内置自检：纯逻辑用例在启动时跑一遍，logcat 输出 PASS/FAIL。
- 产出一份"文档缺口清单"，并当场回填。

### 非目标

- 撤销、排行榜、音效、多主题、5×5/6×6、横屏/平板适配。
- 打包 APK 与安装（本轮只到开发模式运行；打包留作后续）。
- 自定义字体、粒子效果、音效。

### 反目标（即使游戏能玩也算失败）

- 在 `.iyu` 里写 `call`/`addv` 以外的裕语言函数。
- 把状态放在模块级变量里跨 `call` 使用。
- 用 bind mount 投递，或改完源码 `am force-stop` iApp 打断用户正在看的工程。
- 为了动画牺牲状态正确性（连击导致棋盘与视图不一致）。
- 遇到文档没写的 API 直接猜着写，不先探针。

## 4. 工程与文件

新建工程：`android-sync/ProjectApp/com.demo.game2048/`

```
com.demo.game2048/
├── .project / AndroidManifest.xml / icon.png
├── files/ res/ sdk/iapp.sdk build.xml
└── src/
    ├── mian.iyu        # 页面结构 + 事件绑定（只 call）
    ├── game.mjava      # 规则、状态、持久化、自检
    ├── board.mjava     # 棋盘视图构建、渲染、动画、滑动/按键输入
    └── theme.mjava     # 配色、尺寸、drawable 工具
```

**为什么拆三个模块**：`game` 是纯逻辑，`board` 是视图与动画，`theme` 是常量与工具。
**跨模块加载**：用 `i.fn("模块名")` 加载进当前解释器，加载后可直接调；
已在 7 模块 2048 上实测（开发 + 打包均通过）。

## 5. 规则与数据模型

- 棋盘 `int[16]`，`index = row * 4 + col`。
- 行/列抽取后：压缩非零 → 相邻同值合并一次 → 补零。
- 有效移动：`next` 与当前不同；无效移动**不生成新块**。
- 生成：有效移动后随机空格，90% 出 2，10% 出 4。
- 计分：每次合并加合并后的值。
- 判负：没有空格且四个方向都无相邻同值。
- 判胜：任意方块达到 2048 且 `won=false`；弹层可"继续挑战"（`won=true`），此后不再弹。
- 撤销：不做。

### 移动结果结构（供动画使用）

`move(dir)` 内部产出：

- `next[16]`：新棋盘
- `moves[]`：`{from, to, value}`，每个旧方块一条
- `mergedTo[]`：本回合发生合并的目标格
- `spawnIndex`：新块位置（无新块为 -1）
- `scoreAdd`

`next` 与 `moves` 必须在同一遍里算出，禁止动画层自己再推算一遍。

```
root LinearLayout (vertical, #FAF8EF, padding 16dp)
├── header LinearLayout (horizontal)
│   ├── title TextView "2048" (bold, 44sp, #776E65, weight 1)
│   ├── scoreBox LinearLayout (vertical, 圆角 #BBADA0)
│   │   ├── "分数" 12sp #EEE4DA
│   │   └── 数值 20sp #FFFFFF bold
│   └── bestBox LinearLayout (同上)
├── actions LinearLayout (horizontal)
│   └── newGame Button "新游戏" (#8F7A66 / 白字 / 圆角)
├── boardEx FrameLayout (width=-1, height=-2)
│   └── boardFrame FrameLayout (id=31, 运行时设为正方形, 居中, 圆角 #BBADA0)
│       └── overlay LinearLayout (id=33, match_parent, 半透明, visibility=gone)

│           ├── overlayContinue Button
│           └── overlayRestart Button
```

- `boardFrame` 的尺寸在运行时计算：`side = min(可用宽度, 可用高度)`，设为精确 px；`boardEx` 负责占位。
- 16 个格子背景与 16 个瓦片都由 `board.mjava` 动态加进 `boardFrame`。
- `overlay` 是 ppt 里的固定子控件，**每次重建瓦片后 `overlay.bringToFront()`**，保证弹层在最上。
- 弹层按钮用 ppt 的 `clicki` 绑 `call`，避免动态创建控件时再处理监听器。

### 6.3 尺寸

- 格子边距 `10dp`，棋盘内边距 `10dp`，圆角 `6dp`。
- 棋盘边长 = 可用宽高的较小者；瓦片边长由棋盘边长、内边距、间隙算出，全部 dp→px。
- 滑动判定阈值 `24dp`，取位移较大的轴作为方向。

## 7. 输入

### 7.1 滑动

- 主方案：`boardFrame.setOnTouchListener(new View.OnTouchListener(){...})`。
  - `ACTION_DOWN` 记录 x/y；`ACTION_UP` 算 `dx/dy`，超过阈值后判方向并调 `move(dir)`。
  - 返回 `true` 消费事件。
- 探针 P1 必须确认：BeanShell 匿名接口里能否访问外层方法与变量、`MotionEvent` 能否正常拿到 `getAction/getX/getY`。
- 回退：
  1. 匿名类里只调无参模块方法，坐标经 `i.sss` 传递。
  2. 若连模块方法都调不到，改用 iApp `touchmonitor` 事件（探针 P1b 测它到底能传什么）。
- 记录：无论走哪条，`touchmonitor` 的真实能力都写进 `events-guide.md`。

### 7.2 方向键

- 主方案：`boardFrame.setFocusableInTouchMode(true); requestFocus(); setOnKeyListener(...)`，识别 19/20/21/22。
- 并列探针 P2：
  - **静态分析** iApp dex 里 `downkey/upkey` 的派发参数，确认事件体能否拿到 keycode。
  - **运行期**在 `<UIEventset>` 里挂 `downkey/upkey`，日志打印所有可见参数形态。
- 回退：`activity.getWindow().getDecorView().setOnKeyListener(...)`；或 iApp `downkey` 若带 keycode 就直接用。
- 验收：`adb shell input keyevent 19/20/21/22` 与用户在模拟器按键都要生效。

## 8. 动画

### 8.1 观感

| 阶段 | 时长 | 内容 |
|---|---|---|
| 滑动 | 110ms | 每个旧瓦片从旧格中心平移到新格中心 |
| 合并 | 100ms | 目标格先 `scale 1→1.18`，再 `1.18→1` |
| 生成 | 100ms | 新瓦片 `scale 0→1`、`alpha 0→1` |
| 总锁 | ≈210ms | 期间只接受一次"待处理方向" |

- 合并时两个源瓦片同时滑到目标格，动画结束后统一按 `next` 重建视图。
- 输入锁：`i.sss("g.busy")`；动画中收到方向只存 `g.pendingDir`，结束后若有待处理方向立即执行。
- 首页 `loading` 恢复存档时不做动画。

### 8.2 驱动方式（探针决定）

- **首选**：`ValueAnimator.ofFloat(0,1)` + 匿名 `AnimatorUpdateListener`（接口）。
- 需要探针 P3 确认：
  1. `ValueAnimator` 在 BeanShell 里可构造；
  2. 匿名监听器能访问外层局部变量/数组；
  3. `view.postDelayed(new Runnable(){...}, ms)` 可用。
- 回退 A：监听器不闭包 → 动画参数全部写进 `i.sss`，监听器只调无参方法 `board.tickAnim()`。
- 回退 B：`AnimatorListenerAdapter`（抽象类）不可用 → 结束判定放在 update 回调里 `fraction>=1`。
- 回退 C：完全没有 Animator → `postDelayed` 手写 16ms 帧循环，进度按 `SystemClock.uptimeMillis()` 计算。
- 回退 D：动画彻底不可用 → 只做"瞬间刷新 + 新块 alpha 进场"，并在 SKILL 标注。

## 9. 持久化

- 文件：`activity.getFilesDir()/game2048.save`（应用私有，无需权限）。
- 失败回退：`activity.getExternalFilesDir(null)/game2048.save`。
- 格式（纯文本，一行一项）：

```
v1
score=<int>
best=<int>
won=<0|1>
over=<0|1>
board=<16 个逗号分隔整数>
```

- 时机：每次有效移动、合并计分、胜负变化、新游戏后立即写；不依赖生命周期回调。
- 读：`init()` 时读；解析失败当作新局，并 `i.syso("G2048 save-corrupt")`。
- 验收：玩几步 → 杀掉 iApp 进程 → 重开工程 → 分数/棋盘/最高分一致。

## 10. 自检与证据

`selftest()` 在 `loading` 里执行，用纯数组调用逻辑层，日志格式统一：

```
G2048 TEST <name> PASS|FAIL <detail>
```

最少覆盖：

1. 单行左移合并：`[2,2,4,4] → [4,8,0,0]`，加分 12
2. 不二次合并：`[2,2,2,2] → [4,4,0,0]`，不是 `[8,0,0,0]`
3. 不跨零合并：`[2,0,2,0] → [4,0,0,0]`
4. 无效移动不生成新块、不加分
5. 四方向对称：同一局面右移等于镜像后左移
6. 判负局面识别
7. 判胜触发（合成 2048）
8. 存档序列化 → 反序列化往返一致

UI 部分靠用户操作 + `adb logcat` + `screencap` 双证据；每个动作日志带状态快照：

```
G2048 move dir=L from=... to=... score=... spawn=...
```

## 15. 实际实现与验证结果（2026-10-26）

实现时的偏离，均已在 `docs/evidence.md` 与 `cases/14-2048.md` 记录：

- **七模块**：按初始方案 B8 拆成 `game.mjava` facade + `g2048_util/core/store/ui/anim/input`；
  加载用 `i.fn("模块名")`（当前解释器，直接调），源码直接打包、不合并。
  `i.d.f` 仅开发模式；`i.call` 要按 `i.call("mjava","模块.方法",Object[])` 的顺序。
  第一次拆分时 `layout()` 在 `importAll()` 前调用 `u_st`，触发
  `Command not found` 并中断整个方法；已把 `importAll()` 提到每个 public 入口第一行。
  详见 `references/modularization-guide.md` 与 `cases/15-modularization.md`。
- **动画驱动**：用 `ObjectAnimator` 平移/缩放 + `postDelayed(匿名 Runnable)` 分段收尾，没有用 `ValueAnimator` 的 update 监听，也没有用 `AnimatorListenerAdapter`（抽象类不可匿名继承）。
- **滑动**：mjava `setOnTouchListener`，没有走 `touchmonitor` 事件。
- **键盘**：`downkey` 事件体传 `st_kC`；随后注释掉 `setOnKeyListener` 做隔离复核，方向键仍全部生效 → 单条入口就够。
- **持久化**：`activity.getFilesDir()/game2048.save`，每次有效移动立即写。
